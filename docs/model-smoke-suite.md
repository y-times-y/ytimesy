# Model smoke suite

`scripts/model-smoke-suite.ts` is a development-only regression gate for the builder harness across models. It refuses to run unless `DATABASE_URL` and `supabase/.temp/project-ref` point at the development project and both `--live` and `--max-cost <USD>` are given. Run it with `node --env-file=.env --import tsx scripts/model-smoke-suite.ts --live --max-cost 10`. By default it runs five small tasks (`count-script`, `edit-function`, `fix-failing-test`, `rename-function`, `agents-rule`) against `codex:gpt-6.1-sol` (the Codex subscription) and, through the owner's OpenRouter connection, `anthropic/claude-sonnet-5.5`, `google/gemini-3.8-flash` and `deepseek/deepseek-v4.1-flash`. Narrow it with `--models a,b` (`codex:<id>` selects the subscription) and `--tasks x,y`; `--concurrency` (default 5), `--turn-timeout` seconds (default 300), `--out <file>` and `--price model=in:out` (USD per million tokens, used for the cost cap) are optional. Each run creates its own disposable VM from the cheap base snapshot, writes a tiny fixture repository, starts one root builder turn on the development edge executor, then runs a deterministic shell verifier on the VM. VMs and sessions are deleted in `finally` blocks even on failure or Ctrl-C. Before a run starts, its worst-case spend is reserved against the cap, and a run whose recorded usage goes past that reservation is cancelled.

Reading the output: one line prints as each run finishes, then a per-run table and a per-model summary. `verify` is the verifier's exit status, which is the pass/fail signal. `state` is the turn's final state. `tools`/`failed` count tool calls from the session items, with failures grouped by tool (for example `apply_patch:2`). `steps` counts assistant messages. `in`/`out`/`cache%` come from the turn's recorded API usage, and `usd` is an estimate based on list prices. Failure reasons and error items, with secrets redacted, print below the tables. The full record, including verifier output and per-tool counts, goes to the JSON file (default `/tmp/model-smoke-<timestamp>.json`). The exit code is non-zero when any run fails verification, so compare the per-model `verified` and `failed` columns before and after a harness change.
