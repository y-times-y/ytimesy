# Model smoke suite

`scripts/model-smoke-suite.ts` is a development-only regression gate for the builder harness across models. It refuses to run unless `DATABASE_URL` and `supabase/.temp/project-ref` point at the development project and both `--live` and `--max-cost <USD>` are given. Run it with `node --env-file=.env --import tsx scripts/model-smoke-suite.ts --live --max-cost 10`. By default it runs five small tasks (`count-script`, `edit-function`, `fix-failing-test`, `rename-function`, `agents-rule`) against `codex:gpt-6.1-sol` (the Codex subscription) and, through the owner's OpenRouter connection, `anthropic/claude-sonnet-5.5`, `google/gemini-3.8-flash` and `deepseek/deepseek-v4.1-flash`. Narrow it with `--models a,b` (`codex:<id>` selects the subscription) and `--tasks x,y`; `--concurrency` (default 5), `--turn-timeout` seconds (default 300), `--out <file>` and `--price model=in:out` (USD per million tokens, used for the cost cap) are optional. Each run creates its own disposable VM from the cheap base snapshot, writes a tiny fixture repository, starts one root builder turn on the development edge executor, then runs a deterministic shell verifier on the VM. VMs and sessions are deleted in `finally` blocks even on failure or Ctrl-C. Before a run starts, its worst-case spend is reserved against the cap, and a run whose recorded usage goes past that reservation is cancelled.

Reading the output: one line prints as each run finishes, then a per-run table and a per-model summary. `verify` is the verifier's exit status, which is the pass/fail signal. `state` is the turn's final state. `tools`/`failed` count tool calls from the session items, with failures grouped by tool (for example `apply_patch:2`). `steps` counts assistant messages. `in`/`out`/`cache%` come from the turn's recorded API usage, and `usd` is an estimate based on list prices. Failure reasons and error items, with secrets redacted, print below the tables. The full record, including verifier output and per-tool counts, goes to the JSON file (default `/tmp/model-smoke-<timestamp>.json`). The exit code is non-zero when any run fails verification, so compare the per-model `verified` and `failed` columns before and after a harness change.

## Free models (development only)

`--models free` runs OpenRouter's $0 `:free` variants with tool calling, one per family (`google/gemma-4-31b-it:free`, `nvidia/nemotron-3.5-super-vl:free`, `cohere/north-mini-code:free`, `dots-studio/dots-3-note-preview:free`, `poolside/laguna-s-2.1:free`); `free` can be mixed with other ids. Free variants are not on the curated list, so the development edge executor must be deployed with `YTIMESY_DEV_ALLOW_ANY_MODEL=1` (the suite sets it for its own local catalog check). Production ignores the flag. With the flag, an unlisted `:free` model passes the OpenRouter adapter unpinned; unlisted paid models stay refused. Free models are priced at $0, so `--max-cost 0` is accepted when every model is free (the VMs still cost Freestyle time). OpenRouter allows 20 `:free` requests per minute and 50 per day (1,000 once 10+ credits were ever bought), so free runs default to concurrency 1 (at most 2), and the suite reads the key's remaining daily free requests and refuses to start when the runs need more than about 40 requests each. The saved OpenRouter connection's catalog must list the model; re-save the connection to refresh it.

## Native Codex comparison

`scripts/native-vs-harness.ts` runs the same tasks (shared through `scripts/smoke/builder-harness.ts`) on the native Codex CLI and on the builder with the same subscription model, to check a harness change in about ten minutes. Run it with `node --env-file=.env --import tsx scripts/native-vs-harness.ts --live`. The native arm runs `codex exec --json` locally in a fresh temp repository with the `workspace-write` sandbox and a clean `CODEX_HOME` (only `auth.json` is linked, so user config, `AGENTS.md`, MCP servers, plugins and hooks stay out). The harness arm uses the smoke suite's disposable-VM path with `codex:<model>`. Options: `--model` (default `gpt-6.1-sol`), `--effort` (default `medium`, sent to both arms), `--tasks`, `--repeat N`, `--arms native,harness`, `--native-concurrency` (default 3), `--harness-concurrency` (default 5), `--turn-timeout` seconds (default 300), `--codex-bin` and `--out`. The output header lists what each arm measures differently; native step counts are estimated from the JSONL event stream.
