# Provider reasoning replay and compaction evidence

Checked 2026-10-04 against official provider pages using search, page opens, and `agent-browser read`. These are documentation findings, not live inference proofs. Model names describe the checked sources, not additions to ytimesy's catalog. OpenAI/Codex is outside this table's research scope.

Reasoning replay, server conversation storage, provider compaction, and client summarization are separate capabilities. An opaque field's name does not establish its contents; the statements below follow each provider's explicit description. “Not established” means the checked sources do not establish the capability, not that no such capability exists.

## Anthropic prefix rules that affect this harness

On-demand compaction preserves retained thinking only when every compaction since it was generated used a preserved-thinking model, retained messages form the unchanged immediate suffix of the summarized prefix, and `system` plus non-deferred tools stay fixed. The first retained message must differ in role from the last summarized message and cannot be a mid-conversation system message. Additions, omissions, or role merging at that boundary can invalidate reasoning. [Compaction and preserved thinking](https://platform.claude.com/docs/en/build-with-claude/compaction-thinking-blocks).

Prefix enforcement starts with Fable 5.1; Mythos 5.1 and earlier models do not run that check. New accounts created from August 31, 2026 enforce it by default; older accounts may need explicit binding controls. Incompatible model thinking is dropped. Sonnet 5.5 thinking also has account binding. A successful request on an older key therefore does not validate replay for all users. [Preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking).

To test preserved recent thinking, request the `thinking-binding-controls-2026-08-01` beta with mismatch behavior `error`; verify the first post-compaction response and `input_transformations`, not only the compaction response. Production `drop_block` avoids a request failure but loses the affected reasoning and must be reported as such. Threshold compaction cannot keep retained thinking in the same way on Fable 5.1, Opus 5.5, and Sonnet 5.5. [Verification procedure](https://platform.claude.com/docs/en/build-with-claude/compaction-thinking-blocks#check-that-the-kept-thinking-held), [compaction comparison](https://platform.claude.com/docs/en/build-with-claude/compaction).

## Integration implications

Treat each adapter capability separately: ordinary opaque replay, plaintext replay, server continuation, native compaction, and whether recent reasoning survives a rewritten prefix. Preserve canonical original provider items rather than reconstructing them from visible text. Bind checkpoints to connection/model and provider compatibility rules; a shared OpenAI-compatible JSON shape does not establish matching semantics.

Review any fallback that prepends a custom summary while retaining recent Anthropic thinking. On models enforcing prefix binding, unchanged signed blocks can still fail because their earlier context changed. Use native compaction under its conditions or remove affected reasoning and record its loss. This is a source-backed risk to inspect, not a claim that a failing production request was reproduced.

For xAI, native compaction is a concrete adapter option to investigate. For Gemini, using managed Antigravity for its automatic compaction would also adopt its harness and environment workflow; it is not established as a compaction service for ytimesy's existing loop. For Meta, the documented path is client compaction with intact recent ciphertext. For plaintext providers, exact history replay deserves adapter verification, but it should not be called encrypted or lossless compaction.
