# Capy public benchmark trace sources

Inspected 2026-10-07. Read-only public-artifact research; no inference runs. Frozen future evaluation tasks `session-window-debug`, `wal-recovery-ordering`, and `nextjs-performance` were excluded from trace-body inspection. Trace inspections below extract metadata and event/tool names; they do not establish production behavior.

## Canonical artifacts and provenance

The canonical public artifact dataset is [harborframework/terminal-bench-2-leaderboard on Hugging Face](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard). Its [Capy GPT-5.5 submission directory](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/tree/main/submissions/terminal-bench/2.0/Capy__GPT-5.5) contains five evaluation directories and `metadata.yaml`, confirmed through its [public directory API](https://huggingface.co/api/datasets/harborframework/terminal-bench-2-leaderboard/tree/main/submissions/terminal-bench/2.0/Capy__GPT-5.5?limit=1000). An older [Capy Claude Opus 4.6 directory](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/tree/main/submissions/terminal-bench/2.0/Capy__Claude-Opus-4.6) also exists. Latest means latest Capy model submission located in these inspected sources; this is not a claim that Capy has never evaluated another model privately.

The [official Terminal-Bench 2.0 leaderboard](https://www.tbench.ai/?version=2.0) displays Capy GPT-5.5 at 83.1% ± 2.1, with model release date Apr 23, 2026. Its public `leaderboard-read` response identifies the agent as `capy-build`, agent version `unknown`, `verified: false`, and `n_trials: 0`. This distinguishes a published vendor submission from a maintainer-verified reproduction. The [website's primary source](https://github.com/harbor-framework/terminal-bench-website/blob/main/lib/leaderboard.ts) documents the public, unauthenticated read endpoint and the 2.0 package/leaderboard identifiers. The query was `{"package":"terminal-bench/terminal-bench-2","name":"2-0"}` at `https://ofhuhcpkvzjlejydnvyd.supabase.co/functions/v1/leaderboard-read`.

The rendered 2.0 row currently clicks to an incorrect 4.0 URL that returns Page not found. The [corrected Harbor row](https://hub.harborframework.com/datasets/terminal-bench/terminal-bench-2/latest/leaderboards/2-0/rows/02e83b89-a3e1-4b8b-8733-b1bc70da7515) loads, but shows 0/0 trials and no token data. [prime-radiant-inc's fetch script](https://github.com/prime-radiant-inc/terminal-bench-analysis/blob/main/fetch_data.py) supplied the discovery pointer: it mirrors `result.json` from the exact HF dataset above. Its mirrored results were not used as the authority for the observations below.

## What the canonical trial config proves

For [adaptive-rejection-sampler R2qYWGE config.json](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/resolve/main/submissions/terminal-bench/2.0/Capy__GPT-5.5/eval-terminal-bench-2-0-gpt-5-5-7c56da63-1777349417783/adaptive-rejection-sampler__R2qYWGE/config.json), allowlisted fields are:

- Agent import: `adapter:CapyBuildAgent`; model: `openai/gpt-5.5`; agent kwargs: `{}`.
- Environment: `daytona`; force build false; delete true; CPU, memory and storage overrides null.
- Global timeout multiplier: 1.0; explicit agent and verifier timeout multipliers null.

The config alone does not expose the adapter implementation, system prompt, full tool definitions, exact context limit, compaction thresholds, or absolute per-task timeout. Environment and timeout configuration should not be generalized to Capy's production hosting.

## Observed loop evidence

Canonical [adaptive-rejection-sampler stdout](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/resolve/main/submissions/terminal-bench/2.0/Capy__GPT-5.5/eval-terminal-bench-2-0-gpt-5-5-7c56da63-1777349417783/adaptive-rejection-sampler__R2qYWGE/agent/command-0/stdout.txt) begins with process metadata `mode=build`, `handoff_enabled=true`, `run=1`, `repeat=1`; loop start records `tool_count=13`. Its event counts are 14 iteration starts, 14 LLM request starts, 13 tool starts, and one verification prompt. Tool starts: `bash_run` 9, `ls` 2, `write` 1, `edit` 1. The first completion triggers `agent.loop.verification_prompt` with reason `first_completion_detected`, and eventual stop reason is `no_tool_calls`.

Its [canonical result.json](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/resolve/main/submissions/terminal-bench/2.0/Capy__GPT-5.5/eval-terminal-bench-2-0-gpt-5-5-7c56da63-1777349417783/adaptive-rejection-sampler__R2qYWGE/result.json) reports agent `capy-build`, version `unknown`, duration 462,310 ms, 14 iterations, `totalTokens` 467,332, cost USD 1.74205, and agent metadata `success: true`. That success flag is an agent execution result; evaluate verifier reward separately. Input/output token fields in this result are null, so `totalTokens` should not be described as uncached billable input tokens.

A longer independent canonical sample, [make-doom-for-mips 9HRC2X7 result.json](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/resolve/main/submissions/terminal-bench/2.0/Capy__GPT-5.5/eval-terminal-bench-2-0-gpt-5-5-7c56da63-1777349417783/make-doom-for-mips__9HRC2X7/result.json), reports **73 iterations**, duration 863,811 ms, `totalTokens` 6,055,559, cost USD 6.410435, and no exception type. Its [stdout](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/resolve/main/submissions/terminal-bench/2.0/Capy__GPT-5.5/eval-terminal-bench-2-0-gpt-5-5-7c56da63-1777349417783/make-doom-for-mips__9HRC2X7/agent/command-0/stdout.txt) contains 73 iteration/request starts, 76 tool starts, one verification prompt, one loop start and one loop stop. Tool starts are `bash_run` 32, `read` 24, `grep` 15, `ls` 2, `glob` 2, `multi_edit` 1. This directly proves that this benchmark execution supports more than 30 iterations. It does not identify its maximum iteration limit.

The root research agent independently inspected a canonical `fix-git` sample: 21 iterations, duration 118,921 ms, `totalTokens` 276,922, cost USD 0.709152. Iteration 19 without tool calls triggered `first_completion_detected`; iterations 20 and 21 continued verification before `no_tool_calls` termination. Its launcher used Build mode, GPT-5.5, `--reasoning xhigh`, and `--handoff`. Tool counts were `bash_run` 22, `ls` 1, `read` 4, `edit` 2, `glob` 2: 31 calls total. Summed logged LLM durations were 118,602 ms versus 312 ms for tools, approximately 99.7% of agent elapsed duration in LLM requests for this sample. This describes one run, not a fleet-wide latency breakdown. These numbers are root-agent observations; the two directly inspected sources above provide this note's independently reproduced event evidence.

Across the two independently inspected canonical stdout samples, the listed events contain no delegation or child-agent event, no wakeup event, and no handoff/compaction event. `handoff_enabled=true` proves the feature was enabled in process configuration, not that a handoff occurred. `tool_count=13` proves a count at loop initialization, not the identities or definitions of all 13 tools. Absence from these samples is not evidence that Capy's full benchmark suite or production service lacks those mechanisms.

It does not include the system prompt or full tool definitions. Prefer canonical stdout and results for instrumentation, costs, limits and recovery conclusions.

## Production orchestration boundary

[Capy's July agentic-coding article](https://capy.ai/articles/agentic-coding) describes Captain planning, Build execution in isolated Ubuntu VMs, Review, parallel independent work and branch-sequenced dependencies. Its [Aug 11 Beta changelog](https://capy.ai/changelog/beta) describes threads waking for CI completion, review and PR merge, and tasks splitting work across children. Those are first-party product descriptions. The inspected benchmark configuration explicitly identifies a **Build agent adapter** and Build mode. It does not show Captain creating a dependency graph, Build children coordinating, Review reviewing a PR, or CI/event wakeups. The public benchmark score therefore supports this benchmark Build execution, not a demonstrated Captain/Build/Review production workflow.

Further work needed for global trace conclusions: enumerate all five canonical runs with paginated API traversal, count events across non-frozen trials, and locate the installed adapter's documented source/prompt/tool manifest if publicly available. A recursive API response with 1,000 entries was capped and was not used as a complete run inventory.

The root agent also inspected [Capy's current public API streaming documentation](https://docs.capy.ai/api-reference/streaming): public tool activity is a rendered summary rather than raw arguments/results, and reply events do not include internal reasoning. A production API stream consequently cannot by itself reveal the hidden system prompt, complete execution mechanics or raw tool payloads. That API disclosure boundary should not be confused with the richer benchmark stdout artifacts.
