# Devin and Vorflux harness evidence

Checked 2026-10-03 against public first-party documentation using the isolated `agent-browser --session devin-vorflux-research` session. No authenticated product runs, paid inference, account changes, or performance tests were performed. “Documented” below means a vendor documents the mechanism; it does not mean we independently verified implementation or reliability. Marketing quality/cost claims are labeled separately. Current pages generally have no publication date, so this is an access-date snapshot, not a release chronology.

## What “harness” means in this comparison

The useful comparison is the system around inference: models and role routing, tool execution, persistent context, planning and delegation, validation, controls, recoverability, and the user’s ability to inspect and redirect work. Do not equate a model name, agent mode, or benchmark with the complete system. Devin Cloud and Devin CLI are distinct surfaces; CLI-specific features below must not be silently attributed to Cloud.

## Devin / Cognition

### Loop, runtime, and model ownership

- Cloud Agent mode can edit code, execute commands, browse, test, and create PRs. Ask mode explores indexed code and scopes a task before producing an execution prompt. The cloud selector currently documents Lite, Normal, Ultra, Fusion, and SWE-2 research preview, with admin-controlled availability and mid-session changes taking effect on the next message. The same page retains older default/Fast Mode wording: treat this as documentation overlap, not a precise invariant UI inventory. [First session](https://docs.devin.ai/get-started/first-run)
- The platform supplies shell, IDE, and browser access to a development environment. Users can inspect and take over work in the IDE and interactive browser. Public product docs do not disclose the complete cloud prompt loop, exact per-step routing for Normal/Ultra, internal context budget, or termination policy. [Introduction](https://docs.devin.ai/get-started/devin-intro)
- Computer Use has an explicitly documented screenshot → identify elements → act → wait/observe → repeat loop, with a 1024×768 display. This supports graphical applications beyond web pages; it is evidence about the computer-use tool loop, not the entire coding loop. Outposts need platform display/OS permissions supplied by the operator. [Computer Use](https://docs.devin.ai/work-with-devin/computer-use)
- CLI supports model choice, reasoning levels, and models from Cognition and other vendors. Its family aliases resolve to latest versions. [CLI models](https://docs.devin.ai/cli/models)
- CLI Adaptive evaluates requests and routes simple work toward efficient models and complex work toward more capable models; exact router implementation and candidate ordering are not published there. Enterprise enablement is required. [Adaptive](https://docs.devin.ai/cli/adaptive)
- CLI Fusion pairs a frontier lead for planning/critical decisions/review with a cheaper sidekick for mechanical implementation, builds, tests, and verification. Users pick pairing, effort, and fast variants. Availability is version/plan gated. “Frontier intelligence for cheaper” is a vendor quality/cost claim, not independently established here. [Fusion](https://docs.devin.ai/cli/fusion)

### Context, knowledge, skills, and learning

- Repository indexing powers Ask Devin/DeepWiki and is explicitly separate from executable environment configuration. The default branch is indexed; additional branches can be selected. This documents a repository understanding surface, not the retrieval algorithm or guarantee of instant freshness. [Indexing](https://docs.devin.ai/onboard-devin/index-repo)
- Skills are reusable `SKILL.md` procedures from connected repositories or scoped plugins. At session start, indexed skills and disk-scanned skills are merged; branch-local disk versions override matching indexed versions, with rescans on clones. Initially only names/descriptions are supplied; invocation loads the body as system-level context. `allowed-tools` and user-only triggers constrain activation. Only one active skill is supported, so a new one replaces the previous one. Devin can propose learned workflows as skill PRs. [Skills](https://docs.devin.ai/product-guides/skills)
- Knowledge historically uses trigger descriptions, relevant retrieval, repo pins, and suggestions from feedback. The current guide says Knowledge notes are being retired in favor of managed-plugin Skills, retaining content/scope/folder/pin metadata. Consequently, “Devin memory is Knowledge notes” is an incomplete current description. Retrieval scoring, conflict resolution, full-transcript compaction, and autonomous retention/deletion policies are not disclosed here. [Knowledge and migration FAQ](https://docs.devin.ai/product-guides/knowledge)
- Past sessions can be analyzed to extract reasons for failure, improve prompts/playbooks, and consolidate knowledge. Those are documented agent capabilities, not evidence of online model-weight learning. [Advanced capabilities](https://docs.devin.ai/work-with-devin/advanced-capabilities)

### Planning, delegation, and durable orchestration

- Managed Devins are coordinator-owned child sessions, normally in isolated VMs. The coordinator scopes work, monitors compute/progress, messages children, resolves conflicts, aggregates outputs, and can sleep/terminate children. Children auto-start by default; disabling **Auto-approve child sessions** inserts a launch gate. Organization permissions can restrict the corresponding management actions. [Managed Devins](https://docs.devin.ai/work-with-devin/advanced-capabilities)
- Dynamic Workflows move structured orchestration into a Python script with `agent`, `pipeline`, `parallel`, and JSON Schema outputs. Calls are recorded against a run ID. Resume re-executes the script, replaying completed results keyed by prompt/schema/settings hash while unfinished or failed work runs in new sessions. Changing prompts invalidates affected downstream work. Scripts must keep nondeterministic world inspection inside recorded agent calls. Default child VMs require git branch handoffs; optional shared-VM agents expose a common working tree and need disjoint writers. Stop sleeps remaining children; the default/max run budget is seven days. Workflow runs auto-approve by default, with a preference to require approval; enterprise enablement is separate. This is concrete documented durability rather than a claim that all model trajectories are deterministic. [Dynamic Workflows](https://docs.devin.ai/work-with-devin/dynamic-workflows)
- CLI subagents have independent conversation/context windows and do not inherit parent conversation history. Explore uses a server-selected/pinned default model; general inherits the parent model; custom profiles can pin another. Foreground permits interactive tool approvals; background permits only previously approved tools. Interrupt parks workers; resuming a failed/cancelled/completed worker is foreground. Nesting is disabled by default, with experimental custom-profile depth overrides. The CLI panel does not currently identify the active subagent model. These policies are documented specifically for CLI, distinct from managed cloud sessions. [CLI subagents](https://docs.devin.ai/cli/subagents)

### Verification and review loop

- Cloud testing mode prepares access/services, reads the diff and code, chooses a focused test flow, records desktop execution, processes annotations/zoom, and returns video. It can be requested mid-session or triggered after PR creation; automatic post-PR testing requires **Pre-approve testing**. Documentation describes execution after green CI and addressed review comments. This recording is intentionally a short sanity check; exhaustive coverage belongs to test suites/CI. Access gaps require help, and failed recording processing can be retried. Testing learnings can become skill PRs. [Testing and recordings](https://docs.devin.ai/work-with-devin/testing-and-recordings)
- Devin Review can send findings on a running session’s own PR back to that session before publishing comments. With Auto-fix enabled, it attempts fixes and publishes unresolved findings; otherwise it only notifies the session. This is gradually rolling out. Review-provider and credential-specific support varies. [Auto-Fix](https://docs.devin.ai/work-with-devin/devin-review#auto-fix)

### Controls, inspection, recovery, and limits

- Progress unifies commands, code edits, and browser activity. Side chats have the session context to that point, may read/search code, but cannot edit or run commands; they preserve the main run. IDE/browser takeover is documented. [Session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)
- Security Profiles control machine egress, MCP allowlists, read-only Devin-management tools, git read-only/full, and GitHub CLI token presence. Mandatory profiles intersect restrictions and cannot be loosened by lower scopes or children. Policies resolve at boot/wake, so updates do not instantly alter running sessions. Outposts must enforce network rules themselves; Cognition supplies policy metadata rather than configuring the operator’s firewall. [Security Profiles](https://docs.devin.ai/product-guides/security-profiles)
- Sessions cannot continue after 30 days; a new session requires re-sharing relevant context. [Common issues](https://docs.devin.ai/admin/common-issues)
- Clear completion criteria, available context, working environments, and bounded tasks are vendor-recommended conditions. The three-hour task rule is a vendor heuristic, not a measured capability ceiling. The introduction explicitly warns behavior may differ and docs may be outdated. [Usage guidance](https://docs.devin.ai/essential-guidelines/when-to-use-devin), [Introduction](https://docs.devin.ai/get-started/devin-intro)

## Vorflux

### Loop and model ownership

- Every session runs a main agent and role slots for explore, plan, build, debug, review, simplify, and testing. Harness Builder maps models and instructions to slots, offers team/personal/session defaults, clones a read-only baseline, and toggles Simplify Review and Testing phases. A failed idle turn can retry using an updated harness. Admin model policy previews affected harnesses/schedules and applies after in-flight turns finish. Custom instructions override default guidance but not safety, PR mode, permissions, or tool constraints. This is an explicitly configurable harness, rather than merely a list of supported models. [Harness Builder](https://vorflux.ai/docs/harness-configurator)
- Marketing presents Connect → Input → Explore → Plan → Build → Judge → Verify → Ship, with cross-lab plan/diff review and testing expenditure comparable to implementation. Those quality/cost assertions and “production-ready” output language are vendor claims. Current named default models are a mutable snapshot, not the system’s defining property. No public source inspected discloses every prompt, loop state transition, token budget, or model arbitration stop condition. [Official homepage](https://vorflux.ai/)

### Persistent context and memory

- Each session mounts an account-shared persistent `/memory/` volume. Categories cover knowledge, per-app testing, per-user preferences, session transcripts, recurring-session state, and reusable scripts. Agents read before work and write learnings back; only the current user’s preference records apply. Used excerpts show as chips and can receive inline correction comments; a read-only live tree exposes whole files. A daily reconciler at 04:00 UTC operates across idle sessions, merges overlap, resolves contradictions, and retires stale records. Agents are instructed to verify remembered facts against current code. Exact retrieval ranking, write concurrency, provenance rules, retention, and reconciler evaluation are not published on this page. [Memory](https://vorflux.ai/docs/memory)
- Transcript UI includes a **Context compacted** event when conversation summarization makes room. The compaction algorithm, threshold, preserved fields, and loss guarantees are undocumented. [Workspace](https://vorflux.ai/docs/session-workspace)

### Planning and delegation

- Plan mode researches code and emits numbered tasks/file paths/dependencies, with an internal review agent’s feedback incorporated before notification. Users comment in batches, inspect versions/diffs, and approve an exact version; approval dispatches independent build tasks concurrently and dependency-bound tasks sequentially. Plan-side chat is read-only, ephemeral, no-tool, and scoped only to plan text/summary, unlike repository-aware investigation. [Plan Mode](https://vorflux.ai/docs/plan-mode)
- Subagents have separate roles and transcripts, collapsible dispatch rows, status/report/artifact cards, activity logs, and explicit timeout/failure display. REST sub-sessions are also exposed. Their exact intra-session filesystem isolation and conflict-resolution algorithm are not established by this page; do not infer isolated VMs for every role from the separate statement that sessions have isolated machines. [Subagents](https://vorflux.ai/docs/subagents), [Product docs](https://vorflux.ai/docs)

### Verification and review

- Testing agents drive Chromium on the session machine and produce screenshots/videos plus a Test Report linking evidence to results. Missing setup can be repaired via a dialog. Testing questions include why verification blocked and what was tried; answers route only to the testing task without pausing the main session. Sensitive answers use named secrets. Desktop takeover and session-scoped public port previews are available. Android uses Redroid; iOS uses remote Macs through CodeBuild and Appetize previews. Evidence remains after archival. Testing questions are currently web-only. [Testing](https://vorflux.ai/docs/testing)
- Auto Review launches review sessions on selected external GitHub PRs, skips bots/agent branches, never pushes to a teammate’s branch, and supports daily limits, repo/author scope, optional testing, and configurable risk scoring. Risk/testing are off by default; configured low-risk PRs can receive approving reviews. Findings and checks/report cards are externally visible. This is more qualified than homepage language about never self-approving: external PR approval can be enabled. Review checks need GitHub App Checks permission and are not available for GitLab/Bitbucket. [PR Reviews](https://vorflux.ai/docs/pr-reviews)

### Steering, permissions, and recoverability

- Chat, terminal, IDE, desktop, artifacts, diffs, plan/test panels, and per-task activity expose work. User terminal commands use a shell separate from agent commands; IDE edits are visible to the agent. The docs do not prove absence of file/process collisions merely because shells differ. [Workspace](https://vorflux.ai/docs/session-workspace)
- Autopilot auto-approves plans and chooses recommended answers, marks those choices in the transcript, and can resolve currently pending gates when enabled. Quick ask uses existing context without code changes or main-run interruption. Machine stop occurs after four inactive hours, or 24 with a preview; sending a message resumes context/workspace. Incognito restricts session visibility, not account/repo credential access, and supports invited teammates. [First session](https://vorflux.ai/docs/first-session)
- Fork carries conversation context; archive releases the machine but retains conversation/PRs/artifacts. Inactive sessions auto-archive after ten days. An archived/idle session can resume on a fresh session with workspace context intact. Exact disk snapshot/replay semantics, uncommitted-file preservation, and process recovery are not specified by that wording. [Lifecycle](https://vorflux.ai/docs/session-lifecycle)
- Secrets use AWS Secrets Manager/runtime environment injection with documented UI redaction. Repo values are delivered when the agent selects the repo; this is not equivalent to a human approval boundary. Incognito session secrets override other scopes and expire on archival. Claims that plaintext never appears in logs/PRs/transcripts were not independently tested. [Secrets](https://vorflux.ai/docs/secrets)
- Browser snapshots retain authenticated cookies/session state per machine and are automatically reused. The docs say rollout is ongoing. Cookie expiry, privilege changes, and actual freshness still require validation. [Browser snapshots](https://vorflux.ai/docs/browser)
- Unknown from sources inspected: hard egress sandbox policy, complete tool permission matrix, reliable cancellation of external effects, checkpoint rollback guarantees, conflict isolation between build subagents, maximum run duration, context corruption rates, and independent end-to-end success statistics.

## Comparison implications, not implementation recommendations

Devin’s strongest specifically documented orchestration distinction here is recorded deterministic workflows with replayable structured agent calls. Vorflux’s strongest explicitly exposed distinctions are per-role harness configuration, account-level file memory with visible excerpts/reconciliation, and a plan-review-build-test pipeline whose intermediate artifacts are steerable. Both vendors document full executable environments, browser evidence, parallel agents, persistent reusable instructions, and human takeover. Feature presence alone does not establish comparative quality, identical isolation, or a dependable “run until done” guarantee. No current live product behavior was verified in this research.
