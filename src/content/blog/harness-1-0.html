Introducing ytimesy harness 1.0

11.01.26

The harness

One lead agent, its tools, subagents that work on their own copies of the code, commands that keep running in the background, and a check before it finishes.

The lead agent

Every task has one lead agent. It reads the task and a short report on the machine it runs on, keeps a plan for long work, does the work itself, brings in subagents when parts of the task can run on their own, reviews and applies what they send back, and decides when the task is done.

It has eleven tools, the same for every model. Anything more specific, such as the browser or the background-command controls, is a command on the machine, described in one line of the instructions, rather than another tool. Long builds, test suites and experiments run in the background: bash starts them, the lead keeps working, and it is told when each one finishes.

Code mode

Most steps need several things at once: a few files, the state of the machine, the output of a test. With run_code the lead writes a short JavaScript program that calls its other tools, runs the independent ones in parallel with Promise.all, and returns only what it needs. A failed call comes back as an error value instead of stopping the program, so one missing file does not sink the rest. One model call does the work of several.

Subagents

When parts of a task can be done on their own, the lead starts subagents with agent and keeps working. A subagent sees only the lead's brief and works in the background; one that writes code does it on its own git worktree, and the lead reviews and applies its work. The lead collects their reports with agent_wait and can stop or re-brief them with agent_send.

The clean-copy check

Before finishing, the lead can run ytimesy-check. It copies only what is delivered, the Git-tracked files and declared outputs, into a clean environment and runs the documented command there.

It catches work that runs on the agent's machine but breaks for the next person: a file never committed, a dependency never declared, or state that exists only in the workspace.
